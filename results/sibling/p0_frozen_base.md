## 2. 截断是怎么来的

- **τ=0.5**：典型过程是"并行提交小错误 → 模型发现矛盾、反复纠结 → 写满被截断"。
  - 小错误的例子：`all all spades`、`spadesades`、`tripleple`、`told::`、`(d + e f + g)`（漏了 `+`）、`3^9` 写成 `19,633`。
  - 之后出现："Wait — the second factor is written as $d + e + g g$"、"I think I'm hallucinating"、"I need to restart"。
  - 9 道丢分题里，至少 6 道在第一次 "Wait" 之前就出现了可以用正则匹配到的重复类错误。正则抓不到漏写和数字错误，所以这是下界。
- **τ=0.7**：丢分题和 0.95 的分叉处大多只是换了个说法，之后走了另一条推理路径。例如写错一个公式后进入长时间反思而被截断。没有看到明显的 token 级重复或漏写。
- 重复词的出现频率（每万字符）：0.95 下 0.08，0.7 下 0.30，0.5 下 4.80，约为 0.95 的 60 倍。

## 4. 结论

1. **激进阈值下兄弟 PI 才有信息量**：KL 从 0.95 下的 0.01，到 0.7 下的 0.09，再到 0.5 下的 0.20。
2. **τ=0.7 不适合这个方案**：冲突只占约 1%，假设 H 不成立（答错的违反率反而更低）。而且 0.7 下的丢分多来自推理路径不同，不是 token 级冲突，LOO teacher 管不到。
3. **τ=0.5 是这个方案的适用区间**：
   - 冲突是 0.7 的 3 倍，七成是强烈反对；
   - 答错的 rollout 冲突更多，配对比较方向也一致（但只有 4 道题有对有错，样本小）；
   - 文本层面能直接看到"冲突 → 纠结 → 截断"这条因果链。
4. 一个强烈反对就可能毁掉整题。按每个位置平均的统计会低估它的影响，应该按"每条 rollout 是否出现冲突"来看。

## 5. 对方案的影响：τ=0.5 需要推广目标分布

原规则 `t = α·onehot(c) + (1−α)·q`，α = 2τ−1，只在 τ > 2/3 时同时满足"不改口"和"并行提交 ⇒ 不动点"。τ=0.5 时 α=0，目标退化成纯 q，teacher 偏向的另一个 token 可能越过阈值（改口）。

建议的推广规则（τ ≥ 2/3 时与原规则完全相同）：

```text
α = max(0, 2τ − 1)
t(c)   = α + (1 − α)·q(c)                     并行提交 ⇔ q(c) ≥ 1/2（不动点）
t(v≠c) = min((1 − α)·q(v), τ − ε)              任何别的 token 都到不了阈值（不改口）
被截掉的概率质量均匀分到整个词表               让 student 变得不确定，也就是推迟
```

- τ ≥ 2/3 时，(1−α)·q(v) ≤ 2 − 2τ < τ，截断项不会生效，与现在的 α=0.4 规则一致。
- τ=0.5 时：t(c) = q(c)，原 token 只有在兄弟基本认可（q(c) ≥ 0.5）时才会并行提交；teacher 强烈偏向另一个 token 时，那个 token 最多拿到 0.5−ε，被截掉的部分摊平，student 不会改口，只会推迟。
- 一个例外：如果整个 block 里没有任何位置过阈值，解码器会只提交置信度最高的那一个。这是单 token 提交，本身不存在并行冲突。
