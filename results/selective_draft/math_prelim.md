# Selective Draft OPSD：MATH 实验设置、结果与下一步想法

## 1. 这次实际训练了什么，推理时怎样使用

在冻结的 LLaDA-8B-Instruct 上增加两个小模块：一个让第 28 层提前读出 token 概率，一个把选中位置的预测转成消息，供后四层使用。原模型的 32 层、词嵌入、最终归一化和 LM Head 都不训练。

这里把“原模型加上新模块”叫 Student，把“不使用新模块的原模型”叫 Teacher。

### 1.1 第一阶段：训练 L28 提前预测 L32 判断的能力

读出路径是：

```text
第 28 层隐藏状态 → 小适配器 → 原来的最终归一化 → 原来的 LM Head → token 概率
```

适配器接在 LM Head 前面，不是后面。它先把隐藏向量压到 64 维，再映射回原维度，并加回输入。这里只训练这个适配器。

对同一个生成中的状态，让原模型继续跑到第 32 层，得到各位置的完整词表概率。用这些概率监督 L28 的读出：

```text
第一阶段损失 = KL（原模型 L32 的概率分布 || 适配器读出的 L28 概率分布）
```

KL 在这里衡量两份预测分布的差别；训练要求 L28 给出尽量接近 L32 的概率。损失在当前 block 仍是 MASK 的位置上取平均。

**这一阶段训练的是“提前读懂原模型最后会怎样判断”。** 没有单独的位置预测头，也没有“位置选对了没有”的监督。位置选择直接使用读出的 token 置信度。

### 1.2 推理：每一步选一个位置 A，把它的当前预测传出去

A 表示一个位置；“A 的内容”表示该位置上的 token。模型每次处理的一组 32 个位置叫一个 block，MASK 表示尚未填入 token。每个去噪步骤重新选择 A：

1. 在当前 32-token block 尚未填入 token 的位置上，用适配器读出 L28 概率。
2. 每个位置取最高 token 概率作为置信度，再选置信度最高的位置作为 A。
3. A 的置信度达到 **0.8**，且至少还有一个其他待填位置时，才发送消息。
4. 消息使用 A 的**整个概率分布**：把词表中各 token 的 embedding（表示这个 token 的向量）按概率加权求和。例如，A 预测 `3` 的概率为 0.8、`5` 为 0.2，消息就包含这两个向量的加权组合，而不是直接把输入填成 `3`。
5. 第二个小模块读取“A 的 L28 隐藏状态 + 这条消息”，生成一个修改量，**只加到 A 的 L28 隐藏状态上**。其他位置依靠第 29–32 层原有的双向 attention 接收影响，没有分别加一条消息。
6. 到 L32 后，按末层概率决定本步提交哪些位置。概率超过提交阈值的候选同时写入；如果没有任何位置超过阈值，至少写入置信度最高的一个。

**0.8 是允许发送消息的阈值，不是最终提交阈值。A 没有被提前锁定：它可以本步不提交，末层预测也可以与 L28 不同。** 下一步会重新选择消息来源。一次推理前向包含原来的 32 层，以及中间的读出和消息计算；推理不运行 Teacher。

### 1.3 第二阶段：训练消息模块，让 B 利用 A 的预测

第一阶段学的是“从 L28 读出 token 概率”；第二阶段学的是“把这份预测传回模型，让其他位置利用它”。**这里只训练消息模块，原模型和读出适配器都固定。**

本次实际训练过程：

1. 当前 Student 完整生成答案，只保留答对的 rollout。从中取一个生成中的状态，A 是这一状态下 L28 读出置信度最高的位置，B 指当前 block 中除 A 外的所有待填位置。
2. **Teacher 看什么：**在同一个状态中，把 A 的 MASK 填成这条 **Student rollout 最终在 A 处写入的 token**，其余输入不变。Teacher 运行完整 32 层，得到 B 的概率分布。
3. **Student 看什么：**A 的输入仍是 MASK，在 L28 把 A 的**当前概率分布**通过消息模块传出去，继续跑后四层，得到 B 的概率分布。

损失为 `KL（Teacher 对 B 的预测 || Student 对 B 的预测）`，比较完整词表概率，在 B 的各位置取平均。它要求内部消息尽量重现“输入中已经给出 A”对 B 的影响。

两边使用同一个 A **位置**，但没有强制 Student 本步就提交 A；B 也不一定本步提交。本次 Teacher 使用最终 token（`realized`），不是直接使用当前 L28 首选 token（`argmax`）。**诊断样本中二者约 90% 相同，这些样本的两种 Teacher 监督相同；约 10% 不同。** 不能仅凭这部分不同就认定它导致了掉点。

### 1.4 报告里的三种 Teacher 目标到底是什么

三种方式都先固定上述 A 位置，只改变“给 Teacher 在 A 处填什么”。

| 直白说法 | 代码名称 | Teacher 具体看什么 |
|---|---|---|
| 用完整生成后实际写入的 token | `realized` | 读取这条 rollout 最后在 A 处写入的 token，填给 Teacher。**本次第二阶段训练只用了这一种。** |
| 用当前 L28 最相信的 token | `argmax` | 取适配器在当前状态对 A 预测概率最高的 token，填给 Teacher。不看未来结果。 |
| 分别尝试 A 的多个候选，再平均 Teacher 的预测 | `mixture`，实现为 `mc` 或 `topk` | 对不同候选分别运行 Teacher，再平均其他位置的概率分布。`mc` 按 L28 概率抽样 4 次并平均；`topk` 取概率最高的 4 个候选，按它们重新归一化后的概率加权平均。 |

例如当前 A 可能是 `3` 或 `5`：第二种只给 Teacher 看最可能的那个；第三种分别让 Teacher 看 `3`、看 `5`，再平均它对其他位置的预测。**平均的是概率，不是 token，也不是隐藏向量。**

后两种在本次只用于比较监督分布，没有分别训练模型，因此没有“三种训练方法谁更好”的实验结论。

## 2. 这次实验想回答什么

1. **能否训练一个小适配器，让 L28 提前预测 L32，尤其能否找到一个可靠的高置信 A？** 看全部位置的一致率，以及实际允许发消息的 A 的一致率和覆盖率。
2. **把 A 的内容告诉 Teacher，会不会改变其他位置的判断？不同的 A 来源会给出什么监督？** 比较上面三种方式得到的预测分布，同时检查当前 A 与最终 A 有多常不同。
3. **只在 L28 的 A 位置加入信息，后四层能利用多少？** 用 Teacher 看过 A 后的隐藏状态替换 Student 对应位置的隐藏状态，检查能重现多少完整 reveal 的影响。“reveal”在这里就是把一个 MASK 换成指定 token。
4. **训练消息模块后，是否提高整题正确率，或在维持质量的同时减少实际耗时？** 步数下降本身不算加速，必须把新增计算算进去。

## 3. 关键设置

| 项目 | 本次设置 |
|---|---|
| 模型 | `GSAI-ML/LLaDA-8B-Instruct`，32 层，bf16；冻结原模型，不加 LoRA，不量化 |
| 新增参数 | 读出适配器和消息模块，中间维度均为 64，共约 131 万参数 |
| 数据划分 | `ankner/math-500` 的 7500 道训练题按 seed 42 划成训练 6000、开发 500、分析 500；本次任务评测使用另一个数据集 `HuggingFaceH4/MATH-500` 测试集前 200 题 |
| 第一阶段数据 | 从训练集取 80 题，每题由原模型 greedy（每次选最高概率 token）生成一次；只用答对的 **23 条** rollout，共 **1853 个状态**训练。答错的 rollout 不参与损失 |
| 第一阶段训练量 | 800 次更新，每次 4 个状态；每个状态最多取 32 个待填位置 |
| 第二阶段数据 | 每次更新尝试取 2 道题，由当前 Student 以温度 0.9 生成。每题最多试 8 次，首次答对就停止，只用这条答对的 rollout；8 次全错则丢弃该题 |
| 第二阶段状态与训练量 | 每条答对的 rollout 随机取最多 4 个允许发送消息的状态；每次重新采集。完成 100 次有效更新，另外跳过 20 次无可用状态的更新尝试；共取 240 道题、生成 1130 条 rollout，其中 131 道题在 8 次以内答对 |
| 优化器 | 两阶段均用 AdamW，学习率 `3e-4`，weight decay 为 0，梯度裁剪为 1.0；第二阶段固定第一阶段适配器 |
| 生成长度与停止 | 最多 256 个 token，每个 block 32 个；生成 EOS 所在 block 后停止 |
| 解码规则 | 采集和训练使用固定提交阈值 0.9；评测分别用 0.7、0.8、0.9。步数自适应，**不是固定 128 步**；消息阈值始终为 0.8 |
| 诊断与评测 | 分析集取 64 题，包含答对和答错的轨迹；诊断与任务评测均为 greedy。读出诊断取前 400 个状态，Teacher 诊断取前 150 个有其他待填位置的状态，一致性诊断取前 150 个状态 |
| 计时与 checkpoint | 单张 A100-40GB，任务评测 batch size 为 1，每题计时一次；完整方法使用第二阶段第 100 次更新后的模型，没有比较中间 checkpoint 的任务成绩 |
| Prompt 与评分 | 训练和评测使用同一套 MATH 解题提示；取最后一个 `\boxed{}`，没有则尝试 `<answer>`，沿用现有答案判等规则。本文结果按该规则报告，不修改评分协议 |

“只用答对的 rollout”指最终答案被评分器判对，不保证中间每个推理 token 都正确。诊断状态按轨迹顺序截取，**不是均匀抽取覆盖全部 64 题**，也不能把同一道题的多个状态当作独立题目。

## 4. 结果说明了什么

### 4.1 训练 L28 读出有作用，但不是所有位置都达到 90%

以下比较在相同的 400 个状态、6819 个待填位置上进行，消息关闭：

| 测量对象 | 原始 L28 直接接原 LM Head | 加入训练后的适配器 |
|---|---:|---:|
| 全部待填位置，预测 token 与当前 L32 一致 | 30.7% | **42.0%** |
| 每步选出的 A，预测 token 与当前 L32 一致 | 64.7% | **83.0%** |
| A 达到消息阈值 0.8 时，预测 token 与当前 L32 一致 | 73.1% | **90.3%** |
| 达到消息阈值 0.8 且有其他待填位置的状态占比 | 74.3% | **79.5%** |
| 把消息阈值改为 0.9 时，A 与当前 L32 一致 | 77.5% | **93.6%** |
| 达到消息阈值 0.9 且有其他待填位置的状态占比 | 63.2% | **62.5%** |

**提前读出的目标有正面证据：小适配器确实让 L28 更能提前读出 L32 的判断，挑选高置信位置后尤其明显。** 但 90.3% 是选中 A 的 token 一致率，不是所有位置的正确率，也不是“L28 和 L32 选中的提交位置有 90.3% 相同”。两者还可能一起预测错。

另一个 Teacher 诊断使用 150 个状态，其中 123 个满足发消息条件。在这 123 个状态上，A 的早期预测与该位置**最终 rollout token** 一致率为 **90.2%**。这里的最终 token 来自分析集的原模型 greedy rollout；它不是训练后 Student 在整个测试集上的最终一致率。90.3% 与 90.2% 的样本和比较对象不同。

只开启读出、关闭消息时，64 道评测题与原模型 **64/64 逐字相同**。因此读出变好不代表最终解题能力已经变好。

### 4.2 A 会影响其他位置，但还不能说这种影响有益

在上述 123 个状态上，比较 Teacher 揭开 A 前后的预测。下表是用 KL 衡量的概率分布差别，在其他待填位置及状态上取平均；它衡量“变了多少”，不衡量“变正确了多少”。

| Teacher 在 A 处看什么 | 其他位置的预测相对未揭开 A 时变化多大 |
|---|---:|
| 最终 rollout 写入的 token | 0.163 |
| 当前 L28 最相信的 token | 0.163 |
| 按当前 L28 概率抽样 4 次，平均 Teacher 预测 | 0.172 |
| 当前 L28 概率最高的 4 个候选，加权平均 Teacher 预测 | 0.148 |

**关于 A 的作用，只回答了一半：揭开 A 确实会影响其他位置，这些实际构造的监督也没有完全等于原预测。** 但没有测出“这种影响平均让正确答案更可能”。不能因此宣布 sibling PI 已经有效。

两个数都约为 0.163，不代表两种监督相同：它们可能朝不同方向改变预测。最终 token 监督与抽样平均监督之间的 KL 为 0.071。本次没有训练对照，不能据此认为选哪一种都一样。抽样平均还受到 L28 概率估计和只取少量候选的影响，不能把所有变化都归因于模型本身不自洽。

约 9.8% 的上述高置信 A，与未来最终写入的 token 不同。这说明“Student 此刻主要传 `3`，Teacher 却看最终的 `5`”确实可能发生。**它是训练与推理条件不同步的风险，不是已经定位出的全部掉点原因。**

### 4.3 只改 L28 的 A，不能充分重现从输入处揭开 A 的效果

这个诊断直接取 Teacher 在输入中看过最终 A 后的 L28 隐藏状态，替换 Student 的 A 位置；其他位置保持未揭开 A 时的 L28 状态，再跑后四层。

替换前，Student 与完整 reveal Teacher 的预测差别为 0.163；替换后为 0.137，缩小约 **16.1%**。

**信息传递的检查发现了一个可能的瓶颈：即使 A 的表示直接取自 Teacher，晚层的单位置替换也只重现了部分条件影响。** 这不是准确率提高 16.1%，也不是所有注入方法最多只能做到 16.1%。L24 原始读出在检查的 150 个状态里没有达到 0.8 消息阈值，因此没有可比较的 L24 替换结果。

第二阶段训练损失从前 20% 更新的平均 0.240，降到后 20% 更新的平均 0.170；用向量长度衡量，注入修改量相对于原隐藏状态的大小从约 0.7% 增至 32%。训练确实改变了消息模块，但前后使用不同的生成状态，不能把损失下降直接当成固定样本上的能力提升。修改量变大值得检查，也不能仅凭这个数断定它导致掉点。

### 4.4 完整方法目前没有准确率或实际速度收益

在相同的 200 道 MATH 测试题上：

| 提交阈值 | 原模型正确率 | 加消息后正确率 | 原模型平均步数 | 加消息后平均步数 | 加消息后平均每题多耗时 |
|---|---:|---:|---:|---:|---:|
| 0.7 | 37.5% | 34.5% | 65.96 | 64.59 | +0.226 秒 |
| 0.8 | 39.0% | 38.0% | 79.60 | 77.65 | +0.260 秒 |
| 0.9 | 41.0% | 37.0% | 98.14 | 96.41 | +0.337 秒 |

阈值 0.9 下，原模型答对 82 题，加消息后答对 74 题：有 7 题从错变对，也有 15 题从对变错。平均步数少约 1.8%，但额外计算抵消了收益。仅开启读出，在相同的 64 题上就增加了平均约 0.324 秒。

**提高准确率或实际速度的目标尚未达到。** 200 题的单次初测不足以证明方法必然退化，单个阈值下差异也未达到统计显著；但目前确实没有正收益证据。三个阈值使用相同题目，不是三次独立验证。

一致性诊断另发现 13 个 token 被消息提前推动提交，全部与关闭消息后继续生成所得的 token 一致，原模型平均还需约 1.46 步才提交这些位置。这说明部分决定可以提前，不代表这些 token 一定正确，也不表示每道题都省了 1.46 步。

原模型在被检查的高置信同步提交位置上，揭开 A 后其他位置的首选 token 没变。**这只能说明这些被选中的位置比较稳定，不能说阈值 0.9 下完全没有改善空间。** 对其他待填位置的帮助，以及 Teacher 的改变是否朝向正确答案，仍未证明。

## 5. 新方向：让所有位置共同选择一种解释，再并行生成

**以下是下一步研究想法，尚未实现、训练或验证，不是本次实验的结论。** 不再以“找一个 A，让其他位置跟随 A”为主线，也不把新方向绑定在 L28 或冻结后四层上。

### 5.1 想解决什么

双向 attention 已经让位置共享上下文，但共享上下文不等于共享本次选择。例如，当前有两种合理的后续组合：

- 第一种：位置 B 写 `2`，位置 C 写 `3`。
- 第二种：位置 B 写 `3`，位置 C 写 `2`。

如果只保留各位置自己的概率，再让它们分别选择，就可能拼成 `2、2`。整个 dLLM 的多步生成能形成位置间依赖；这里希望改善的是**同一步内如何共同选择一个合理组合**。

原方案让 A 先提供方向。新方向让所有位置使用同一个“本次采用哪种解释”的选择，不需要任何一个 token 先当领导。

### 5.2 架构准备怎样改变

```text
当前题目、已提交 token 和剩余 MASK
    → 模型读取上下文
    → 一个共享模块形成少量候选解释，并估计各自的可能性
    → 整个 block 共同选择其中一种解释
    → 所有待填位置都根据这个解释，并行预测 token
    → 按固定阈值提交，进入下一步
```

“解释”可以是一组内部向量，不要求先生成一段自然语言推理。共享模块读取当前 block 的全部位置和题目上下文，形成几组候选向量；选中一组后，每个待填位置都读取这同一组向量来预测自己的 token。上面的第一种解释对应 `2、3`，第二种对应 `3、2`。关键是**所有位置共同使用同一个选择**，不能让 B 用第一种、C 用第二种，也不能先把两种解释平均后又退回各选各的。

推理时只能从当前状态选择解释，不能读取未来答案。下一步可以根据新上下文调整解释，但必须尊重已经提交的 token；只修正未提交位置。具体接入哪一层、保留几种解释、是否训练部分主干，还没有确定。

### 5.3 训练需要怎样改变

训练样本要保留“同一条完整续写中，这些位置最后共同写成了什么”。例如，不能把两条正确续写里的 `2、3` 和 `3、2` 拆开混成各位置的平均标签。

一个可考虑的训练方式是：从同一个中间状态取得不同的完整续写，把其中答对的续写作为正样本；在每一种解释下计算**整组 token 一起出现的概率**，再综合不同解释的概率，训练模型提高正确组合的概率。不同解释可以负责不同的合理续写，不要求每种解释都模仿同一份平均答案。答错的续写可以用于检查错误组合；是否将它们作为负例训练，尚未确定。

与本次 `mixture` 的区别是：旧方式先平均 Teacher 在每个位置上的预测，Student 最后仍只得到各位置各自的一份分布；新方式希望一直保留“这些 token 属于同一种解释”的对应关系，并在生成时共同选择。

这里不要求模型提前知道某条随机 rollout 的唯一未来，而是学习多种可能未来中，哪些 token 组合能够一起成立。它尝试用一个共同选择协调所有位置，从而避免 A、B、C 必须先知道彼此最终决定才能预测的循环。

### 5.4 什么结果才说明这个方向有价值

仅仅加一个共享向量、提高参数量，不足以证明解决了问题。需要看到：不同解释确实对应不同的联合组合，模型没有始终忽略它或只使用同一种；在保留当前上下文的情况下，共同选择解释确实减少了互相冲突的输出；这些改善最终带来更好的整题正确率与实际时延权衡。

这个方案也有风险：解释本身选错，可能让多个位置一起错；某种解释内部的 token 置信度很高，不等于这整种解释可靠。固定阈值解码时必须考虑这层不确定性。共享解释是否有足够表达能力、训练会不会退化成普通逐位置预测，以及与已有方法的重合程度，都还需要研究，不能宣称已经解决鸡蛋问题。
