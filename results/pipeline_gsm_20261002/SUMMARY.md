# GSM8K d-OPSD 复现与同步并行 token 协调分析：结果总结（2026-10-03）

> 用途：给人看，也给 AI 做进一步分析。每个数字都可以在同目录下各 run 的 `summary.csv` 和 `report.md` 里查到（含定义和样本量）。逐 token / 逐步的原始表在 `outputs/pipeline_gsm_20261002/<run>/tokens.csv.gz`、`steps.csv.gz`（不进 git）。

## 1. 设置

- 模型：LLaDA-8B-Instruct（4-bit + LoRA r=128），THU d-OPSD 训练，GSM8K train，3×A100、BATCH_DIVIDE=8，共 1344 步，每 64 步存一个 adapter。
- 选 checkpoint：在 300 道 seeded GSM8K test 题上扫描，greedy + 固定预算 128 步（论文协议）。
- 分析：同一批 300 题，T=0.9，生成 256 token，block 32；两种解码：固定预算（128 步，每步 2 个 token）和固定阈值 0.9（每步揭开所有置信度 > 0.9 的位置，至少 1 个）。
- teacher = **base 权重 + PI**（和训练时的 fixed teacher 一致）；PI = 从下一个 block 起随机 25% 的位置填入最终 rollout 的 token。分析用 fp16 重算（和采样器一致）。
- 统计：排除 EOS 和答案结束之后的 token；95% CI 为按 rollout 的集群 bootstrap。

## 4. 解读（Claude 的阅读，供参考）

**最干净的 PI 效应看 base 两列**：student 和 teacher 是同一套权重，只差 PI。

1. **固定预算下，同步提交的兄弟 token 之间是冲突，不是互补。** 揭开兄弟 token 后，student 对 y_i 的信心**下降**（D_S = −0.098，wrong 组 −0.136）；而揭开一个匹配的、之后才解码的对照 token 时，信心**上升**（D_S,ctrl = +0.020）。两者的配对差 −0.117（wrong −0.154），CI 远离 0。所以"同一步并行提交"的 token 确实缺少协调，在答错的 rollout 中更严重。注意：符号和最初的假设（D_S > 0，兄弟提供缺失信息）相反，兄弟表现为**相互冲突**。
2. **PI 部分缓解了这种冲突，但力度有限，且不区分对错。** 有 PI 时，兄弟带来的负面影响从 −0.098 缩小到 −0.075（约 −23%，wrong 组 −0.136 → −0.105）。按原定义，coord = D_S − D_T = −0.022 < 0；冲突情形下更合适的读法是 |D_T| < |D_S|。correct 和 wrong 两组的缓解幅度相近。
3. **PI 让同一步的 token 成组受益（A），超出位置相邻效应**：真实 co-gain 比距离匹配的期望高 +2.9 个百分点（wrong +3.3，p = 0.002）。固定预算下对错两组差别不大；阈值解码下 correct 更高（+7.8 对 +4.7，CI 有重叠）。
4. **PI 倾向于"暂缓"与兄弟冲突的 token**：base 固定预算下，PI 作用的分布是强化 85%、暂缓 12%、改向 3%；兄弟冲突（D_S < 0）时，暂缓或改向的比例从 13.3% 升到 19.6%（wrong：16.8% → 24.8%）。
5. **解码顺序上，teacher 与 student 有明显分歧**：teacher 最想揭开的位置只有约 54% 和 student 实际揭开的重合；约 20% 的已提交 token 在 teacher 看来属于"过早提交"，兄弟冲突时升到 24%。这支持"PI 的一部分作用是调整解码顺序"。
6. **阈值解码下冲突基本消失**：base 的 D_S = +0.012（兄弟反而有帮助），sibling − 对照只有 −0.003，并且 D_S 随 |C_t| 增大而上升（0.009 → 0.018）。这符合阈值解码的前提：置信度都很高的 token 一起提交时是协调的。**冲突主要来自固定预算强制按配额提交**。
7. **训练后模型（step-448）**：g < 0、暂缓比例高达约 63%，主要说明训练后的 student 比 base teacher 更自信，**不是 PI 的作用**。student 自身的兄弟冲突几乎没变（D_S −0.098 → −0.089），但兄弟和对照的差距缩小了（−0.117 → −0.064），因为对照 token 的帮助也变小了（D_S,ctrl +0.020 → −0.025）。在阈值解码下，训练后的模型并行度大幅提高（一步揭开 9 个以上 token 的比例从 39% 升到 64%（按全部 token 统计，含答案结束后的 EOS 填充）），准确率却没有提升。

## 5. 注意事项

1. **teacher 权重不一致**：step-448 那两列里，teacher 是 base 加 PI，student 是训练后的模型，所以 g、D_T、coord、PI 作用分类都混入了权重差异。要看训练后模型上纯粹的 PI 效应，需要用 `--teacher self`（训练后的模型加 PI）重跑分析（每组约 6.5 SU）。
2. **sibling 对比对照，衡量的是"同时提交"对比"先后提交"**：对照 token 是在 y_i 确定之后才解码的。这正是研究对象（并行提交缺少协调），但不等于"任意多给一个 token 的上下文"。
3. 只有一个随机种子、300 题、GSM8K 一个任务、T = 0.9。答对的 rollout 是"整条答对"，单个 token 不一定最优。
4. PI 每步只采样 1 次（25% 的位置随机），g 带有采样噪声；CI 已经反映了 rollout 层面的方差。
