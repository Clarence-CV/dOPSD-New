# Hybrid Path OPSD（基础版）

日期：2026-11-07。状态：方案草稿，未实现。
前一版（Sibling OPSD，截顶 LOO 目标）的结果见 `results/sibling/main_t05_v1.md`。

## 0. 一句话

Teacher 在 τ=0.5 下找到一条**又快又对**的解码路径；Student 沿着这条路径一步一步学：
站在 teacher 第 t 步的状态上，学 teacher 第 t+1 步提交的那组 token，置信度不到 0.95 就用交叉熵推一下。
训练完后，Student 用 **τ=0.95、T=0** 解码，希望一步能提交和 teacher 一样多的 token：更快，而且不掉点。

基础版**不用 LOO**。先看基础版的效果，再把 LOO 过滤作为第二阶段加进去对比（第 6 节）。

## 1. 为什么叫 hybrid

| | 采样设置 | 作用 |
|---|---|---|
| Teacher | τ=0.5，T=0.9，最多 8 次 | 生成训练用的路径 |
| Student | τ=0.95，T=0 | 训练完后评测时的解码设置 |

训练数据来自 teacher 的采样设置，模型最终却按 student 的设置解码，两者不一样，所以不是纯 on-policy，叫 hybrid（混合）。
Teacher 和 Student 是同一个模型（原始模型 + LoRA），teacher 每次都用**当前**模型采样。

## 2. 记号

- Teacher 路径：S₀ → S₁ → … → S_N。S₀ = prompt + 全掩码；每一步解开一些位置。
- C_t：第 t 步提交的位置集合；c_l：位置 l 上提交的 token。
- p_θ(·|S)：当前模型（原始 + LoRA）在状态 S 下某个掩码位置的预测分布。

## 3. 训练流程

### 第 1 步：Teacher 找路径（不算损失）

- 对每道训练题，用当前模型在 τ=0.5、T=0.9 下最多采 8 次，记录完整的解码轨迹。
- 从答对的轨迹里取**解码步数最少**的一条（待定：也可以取第一条答对的，见第 7 节）。
- 8 次都没答对：这道题跳过。

### 第 2 步：Student 逐步学（算损失）

Student 站在 teacher 的状态 S_{t-1} 上（prompt + teacher 前 t−1 步解出的 token），学 teacher 第 t 步提交的 token：

```
L = mean_{t, l ∈ C_t}  max(0, −log p_θ(c_l | S_{t-1}) − (−log 0.95))
```

- 某个 token 的概率不到 0.95，就用交叉熵往上推；已经 ≥0.95，就不管（损失为 0）。
- 每次更新可以从路径中随机抽若干步一起算。因为状态都来自 teacher，各步之间互不依赖，所以不需要按 step1、step2 的顺序学。
- 截断点 0.95 = 评测阈值。如果以后改在 τ=0.9 下评测，截断点也改成 0.9。
- 已经提交的位置、还没轮到的掩码位置都不算损失；梯度只走 LoRA。

### 第 3 步：循环

每次更新都用当前模型重新做第 1 步（和上一版一样现采现训）。模型变快以后，teacher 在 τ=0.5 下能找到更短的路径。

## 4. 评测

- MATH-500，原始模型和训练后的模型都用 T=0 解码，扫 τ ∈ {0.95, 0.9, 0.8, 0.7, 0.5}，比较两条准确率–TPF 曲线。
- 重点看 τ=0.95：TPF 是否明显上升，准确率是否不降。
- 对照：原始模型阈值扫描（job 1127239），以及上一版 sib_t05_v1。

## 5. 训练中盯的指标

| 指标 | 希望看到 |
|---|---|
| C_t 中 p_θ(c\|S_{t-1}) ≥ 0.95 的比例 | 上升 |
| Teacher 选中路径的步数 | 下降 |
| 训练题在 τ=0.95、T=0 下的 TPF | 上升 |
| dev 准确率（τ=0.95） | 不低于原始模型 |
| KL(p₀‖p_θ)（只记录，不进损失） | 看模型偏离原始模型多少 |

## 6. 第二阶段：加 LOO 过滤（基础版跑完再做）

对路径中提交了 ≥2 个 token 的步，用冻结的原始模型做 LOO（其他同步 token 填上、l 保持掩码），q_l(c_l) < 1/2 的 token 不学。
与基础版对比，看过滤是否能减少掉点。这也是区别于 dParallel / SwiftDLM 的关键点。

## 7. 待定
