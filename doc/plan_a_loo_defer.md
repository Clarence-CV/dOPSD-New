# 方案A（初稿 v5）：让每个 token 预见它的兄弟

更新：2026-11-03。状态：**讨论稿，未实现，未提交任何作业**。前情见 [llada2-mini_handoff.md](llada2-mini_handoff.md) §5。

---

## 1. 逻辑主线

**(1) 问题。** 激进阈值下，一步会同时提交好几个 token，而每个 token 是**各自独立**决定的，看不到同一步的兄弟写了什么。所以会拼出各自合理、合起来矛盾的组合。阈值越低，这种情况越多，准确率随之下降。DMax 报告 LLaDA2-mini 在 GSM8K 上，τ 从 0.95 降到 0.5，准确率 92.6% → 78.0%。

**(2) 理想的决定。** 如果一个 token 能看到兄弟写了什么，再做决定，就不会拼出矛盾。这个"看到兄弟之后的决定"，冻结的 base 自己就能算：把兄弟填进去，只留这个位置是 MASK，问 base 会写什么（LOO）。这就是 **teacher**。

**(3) 但 teacher 的好坏取决于它看到的兄弟。** 一份好的特权信息（PI）要同时满足两个条件：

| 条件 | 含义 | 怎么保证 |
|---|---|---|
| **有信息量** | 揭开兄弟，真的会改变这个位置的分布 | 兄弟来自**激进**（τ=0.7）的 rollout：一步提交的 token 多且不确定，彼此依赖强。τ=0.95 下兄弟几乎不改变分布，这正是旧方案只看到加速的原因 |
| **可信** | 兄弟本身是对的，值得去配合 | 兄弟来自**答对**的 rollout。否则 teacher 会去配合错误的兄弟，把"彼此一致但一起错"的组合学得更尖 |

多次采样、碰对一条激进 rollout，就是为了拿到**同时满足这两个条件**的兄弟。

**(4) Student 只学一件事**：在**看不到兄弟**的情况下，一次前向就给出"看到了正确兄弟之后"的分布。也就是**预见它的兄弟**。

**(5) 推理时的效果**，都来自这一件事：

| 兄弟 | teacher 的反应 | student 学到 | 推理时 |
|---|---|---|---|
| 支持这个 token | 更确定 | 推尖 | 更多 token 越过 0.7，一起提交：**加速** |
| 反对这个 token | 不想写它 | 压低，但不改写成别的 token | 跌破 0.7，这一步不提交，下一步看到已写定的兄弟再写：**推迟** |

（精确的目标分布见 §3 "Teacher 的目标分布怎么来"。）

解码器的规则是"置信度 ≥ min(τ, 当前最高 − 1e-5)"，所以每一步至少会提交最高置信的那一个，两个冲突 token 同时被推迟也不会卡住。

## 2. 它学的是"融洽"，还是"答对"？

**目标是融洽：和兄弟保持一致。** 损失里没有直接的对错奖励。目标分布里的轨迹 token c_i 来自答对的 rollout，它的作用是防止 student 改口，不是奖励答对（§3）。

**答对决定的是"和谁融洽"。** 兄弟取自一条已经验证正确的解答，所以和它们保持一致，就等于和一条正确解答保持一致。正确性不是单独的第二个目标，它通过 PI 的选择进入。

所以 student 学到的是：**和正确的兄弟融洽**。这一点不能写成"朝着正确结论跑"：它不知道最终答案，只知道局部应该怎样配合一段正确的解答。

**这背后的假设**，在训练前就要检验：

- **假设 H**：激进解码下答错，相当一部分是因为兄弟之间不一致。换句话说，**答错的 rollout 里不一致的并行组更多**。
- 如果 H 成立：学会和兄弟融洽，就能在 τ=0.7 下把准确率拿回来。
- 如果 H 不成立（答错主要来自别的原因，比如提交太早、分叉点选错）：这个方案仍然能加速，但救不回准确率。

注意：**不需要假设答对的 rollout 处处融洽。** 答对的轨迹里也可能有不一致的组，只是碰巧没影响答案。teacher 会否定这些组，student 正好学会在那里推迟。所以这些组不丢掉。

## 3. 角色

| 角色 | 是什么 | 输入 | 输出 |
|---|---|---|---|
| **Student** | base + LoRA（训练中） | 状态 S_t：答对的激进 rollout 第 t 步提交**之前**的序列，这一步要提交的组 C_t 仍是 MASK | 每个 i∈C_t 的分布 p_i（一次前向，有梯度） |
| **Teacher** | 冻结的 base（关掉 LoRA，无梯度）+ 这条答对的轨迹 | 同一个 S_t，C_t 中**除 i 外**都填上这条 rollout 实际提交的 token，i 保持 MASK | 目标分布 t_i（定义见下） |

readout 与 injector 不再使用（代码保留）。block 内 attention 是双向的，student 每一层都能看到兄弟的隐状态，"预见兄弟"需要的通道本来就有，只缺训练信号。

### Teacher 的目标分布怎么来

关于位置 i，答对的轨迹给了我们**两份证据**：

- **结果的证据**：轨迹在这里写了 c_i，最终走到了正确答案。
- **兄弟的证据**：冻结的 base 看到同一步的其他兄弟之后，在这个位置的分布 q_i（LOO：揭开其余兄弟，只留 i 是 MASK）。

**第一步，LOO 判定这一组是不是不动点。** 如果组里每个位置在看到其他兄弟之后都仍然选自己（argmax q_i = c_i），这组并行提交就是自洽的，是一个不动点。旧方案用不动点**筛数据**：不是不动点的组整题丢掉。这里不再丢弃，不动点从"筛数据的条件"变成"要学会的性质"。训练后，student 自己倾向于只并行提交不动点。

**第二步，把两份证据合成目标**：

```text
t_i = α · onehot(c_i) + (1 − α) · q_i ，   α = 2τ − 1 = 0.4（τ = 0.7）
```

**α 怎么来（不是超参数，由 τ 推出）**。目标在原 token 上的概率是 q_i(c_i) 的一条直线：

```text
t_i(c_i) = α + (1 − α) · q_i(c_i)
```

student 被训练去逼近 t_i，推理时它是否并行提交 c_i，取决于 t_i(c_i) 是否 ≥ τ：

```text
并行提交  ⇔  t_i(c_i) ≥ τ  ⇔  q_i(c_i) ≥ q* = (τ − α) / (1 − α)
```

所以损失不是把情况分成几类，而是只有一条分界线 q*。α 要满足三个要求：

1. **不改口**：teacher 偏向的另一个 token v* 在 t_i 里最多拿到 1 − α，必须到不了阈值：1 − α < τ，即 **α > 1 − τ**。
2. **能推迟**：如果 α ≥ τ，不管 teacher 说什么 c_i 都能过阈值，等于照抄轨迹；所以 **α < τ**。
3. **并行提交 ⇒ 不动点**：q_i(c_i) ≥ 0.5 时，其余 token 加起来不到一半，c_i 必然是 argmax，即 LOO 认可 c_i。令分界线 q* = 0.5：

```text
(τ − α) / (1 − α) = 0.5   ⇒   α = 2τ − 1
```

τ = 0.7 时 α = 0.4：1 − α = 0.6 < 0.7，满足要求 1；α = 0.4 < 0.7，满足要求 2。要求 1 与要求 3 同时成立需要 τ > 2/3；以后若试更低的阈值，要重新推导。

这个保证说的是目标分布 t_i；student 只是逼近它，实际效果用"不动点违反率"检验（§9）。

**正反对比**（τ = 0.7，α = 0.4，分界线 q_i(c_i) = 0.5）：

| 情况 | q_i | t_i | student 学到的行为 |
|---|---|---|---|
| **正：兄弟支持**（不动点） | q_i(c_i) = 0.9 | t_i(c_i) = 0.94 | 推尖 c_i，**并行提交**：加速 |
| **近似平局，c_i 略占上风**（不动点，比如 "the" 和 "a"） | q_i(c_i) = 0.55，q_i(v*) = 0.40 | t_i(c_i) = 0.73 | 仍然提交：不冤枉验证过的写法 |
| **近似平局，v* 略占上风**（不是不动点） | q_i(c_i) = 0.45，q_i(v*) = 0.50 | t_i(c_i) = 0.67，t_i(v*) = 0.30 | 都不到 0.7，**推迟** |
| **反：兄弟强烈反对**（不是不动点） | q_i(c_i) = 0.05，q_i(v*) = 0.9 | t_i(c_i) = 0.43，t_i(v*) = 0.54 | 都不到 0.7，**推迟**，不改写成 v* |

为什么不直接用 q_i，也不直接用 c_i：

- **只用 q_i**（α = 0）：反对的情况下，student 会被拉去**改写成 v***。但 v* 从没被验证过：这条轨迹答对时用的是 c_i。同一步两个 token 同时改口，还可能拼出新的矛盾。
- **只用 c_i**（α = 1）：等于照抄轨迹。不自洽的组合只是碰巧没影响答案，也会被学成"放心并行"。
- **α = 2τ − 1**：v* 永远不会单凭 teacher 越过阈值，所以**不会改口**；**只有不动点才会被并行提交**；不是不动点的就推迟。

推迟不等于否定 c_i：下一步兄弟已经写定，如果 c_i 确实是对的，模型自然还会写 c_i。

## 4. 数据

```text
每次更新，每张卡：
1. 取一道新的 MATH 训练题
2. 当前 student 按 τ=0.7、T=0.9、block 32 解码，最多 8 次，碰到第一条答对的就停
   （沿用现有 root_success_v2，阈值从 0.95 改成 0.7）
3. 8 次都错：跳过这道题
4. 在答对的 rollout 里，从所有 |C_t| ≥ 2 的步中均匀抽 8 步
   （|C_t| > 4 时随机抽 4 个位置，控制 LOO 次数）
5. 对每个抽到的位置 i，跑一次 teacher 前向，得到 q_i
```

- 状态来自 student 自己的 rollout，是 on-policy 的。
- 需要 T>0，否则 8 次都一样，碰不到对的。评测仍用 T=0。
- 错误的 rollout 不参与训练（理由见 §1 (3) 的"可信"）。它们在 Phase 0 中用来检验假设 H。

## 5. 损失

```text
t_i      = 0.4 · onehot(c_i) + 0.6 · q_i                      teacher 的目标分布（§3，α = 2τ − 1）
L_OPSD   = (1/|C_t|) · Σ_{i∈C_t} KL( t_i ‖ p_i )             并行组：预见兄弟
L_anchor = (1/|M_t|) · Σ_{k∈M_t} KL( p0_k ‖ p_k )            M_t = 当前 block 中不在 C_t 里的其余 MASK 位置
L = L_OPSD + 0.1 · L_anchor
```

- p0_k：冻结 base 在同一个 S_t、不填兄弟时的分布（多一次前向）。
- 全词表 forward KL。CLAUDE.md A.3 记录过：on-policy 下 reverse KL 会塌。t 与参数无关，所以 L_OPSD 等价于 0.4·CE(c_i, p_i) + 0.6·CE(q_i, p_i)：前一项是结果的证据，后一项是兄弟的证据。
- 锚定项：LoRA 会改动所有位置，但只有 C_t 上有监督；锚定项让其余 MASK 位置不跟着跑偏。

## 6. 例子

```text
某题在 τ=0.7、T=0.9 下：第 1、2 次答错，第 3 次答对 → 用第 3 次的 rollout

第 3 次的某一步一起提交了 ("5", "x")：
    teacher 对 "5"：揭开 "x"，q("5") = 0.9 → t("5") = 0.94 → student 推尖 → 下次照样并行（加速）
第 3 次的另一步一起提交了 ("=", " 8")，teacher 揭开 " 8" 后：q("=") = 0.05，q("+") = 0.9
    → t("=") = 0.43，t("+") = 0.54 → 两个都不到 0.7 → 下次这一步不提交 "="（推迟）
    不会被改写成 "+"：这条轨迹答对时用的是 "="，"+" 没被验证过
    下一步 " 8" 已经写定，模型再决定这里写什么
```

## 8. Phase 0：训练前检验前提

只用 base，MATH dev128。三个测量各对应逻辑主线里的一个前提：

| 前提 | 测量 | 过关条件 |
|---|---|---|
| 有准确率可救（§1 (1)） | T=0 下 τ=0.95 与 τ=0.7 的准确率 | 差距 ≥ 5 个点（dev128 的标准误约 4 个点） |
| PI 有信息量（§1 (3)） | 在答对的轨迹上，对并行组算 KL(q ‖ p0)，τ=0.7 的轨迹对比 τ=0.95 的轨迹 | τ=0.7 明显更大 |
| 假设 H（§2） | τ=0.7 采样中，"teacher 不同意的并行组"在答错与答对的 rollout 中各占多少 | 答错的明显更多 |

另外记录：

- 8 次内能碰对的题的比例和平均尝试次数，用来估算训练成本；
- 答对的轨迹中，并行提交的位置有多少落在分界线以下（q_i(c_i) < 0.5，即不是不动点），以及它们的 q_i(c_i) 分布（近似平局还是强烈反对）。这个比例很小，说明 t_i 里的 onehot 项影响不大；很大，说明它是关键。

**三条都过才训练。** 第 3 条不过，说明错误主要不来自兄弟冲突，这个方案只能加速。到时再和你讨论是否仍然值得做。

**成本**：fused MoE 约 0.062 s/步（job 3545297）；base 在 τ=0.95 下平均 394 步（job 3526876），每题约 24 s；τ=0.7 估每题 15 s；碰对平均估 3 次。

- 128 × (24 + 15 + 3 × 15) s ≈ 3.0 GPU·h，加 LOO 统计约 0.5 GPU·h；
- 3 卡节点约 1.2 h，**约 4 SU**；申请 `gpu-a100` 2 h。
- 每步时间是外推的，误差可能到 2 倍。

## 9. Phase 1：训练与评测（一个可续跑的作业）

```text
训练 400 次更新
→ dev128（τ=0.7，T=0）评测 base 与 step 100/200/300/400，选最好的
→ MATH-500 test：选中的 checkpoint vs base，τ=0.7 和 τ=0.95 各一遍
```

成本粗估：每次更新约 50 s（碰对约 3 次 × 15 s，加 LOO 与训练），400 次 ≈ 5.5 h；评测约 3 h。合计约 9 节点·h ≈ **27 SU**（误差可能到 2 倍）。Phase 0 跑完按实测重新估，超过 50 SU 先问。

**消融：每一组拿掉逻辑主线里的一环**

| 臂 | 拿掉什么 | 预期 |
|---|---|---|
| **方案A** | — | — |
| PI 来自 τ=0.95 的答对 rollout | **信息量** | 只加速，准确率提升小（复现旧方案的现象） |
| PI 来自不筛对错的 τ=0.7 rollout | **可信** | 准确率提升变小，甚至变差 |
| 剔除 teacher 不同意的组 | **推迟** | 加速仍在，准确率提升变小 |
| base（同阈值）/ DMax-Math | 参照 | — |

**指标**：准确率、TPF、延迟；外加"不动点违反率"，即评测时并行提交的组中，不是不动点（有位置 argmax q_i ≠ c_i）的比例，训练后应该下降。

## 10. 和已有工作的区别

| 工作 | 做了什么 | 区别 |
|---|---|---|
| dParallel（ICLR 2026） | 推理用激进阈值；训练数据是常规解码离线生成、按正确性过滤的轨迹；对轨迹 token 做 CE + 熵最小化 | 我们：轨迹本身就是激进的、on-policy；目标是看到兄弟后的分布，所以也会教"推迟"，不只是"更确定" |
| DMax | 全参微调 + 软 embedding 自修正 | 我们不改解码协议 |
| CoDD（ICML 2026）/ Codpula | 外挂概率电路建模联合分布；Codpula 推理时推迟强依赖 token | 我们不加模块，推理零额外开销 |
| d-OPSD | self-future 做 PI | 我们的 PI 是并行解码独有的：同一步的兄弟 |

**卖点**：并行解码有一种**它独有的、免费的特权信息**：同一步一起提交的兄弟。它只有在**激进且答对**的轨迹上，才同时有信息量又可信。把它蒸馏进模型，每个 token 就学会预见兄弟：自洽就一起写，冲突就等一等。
