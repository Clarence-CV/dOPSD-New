# 扩散语言模型同步解码中的协调缺口：基于 d-OPSD 的现象分析

> 模型 LLaDA-8B-Instruct ｜ 任务 GSM8K ｜ 基线 d-OPSD（清华，*Learning from the Self-future*）｜ 2026-10-03

**摘要**　扩散语言模型（dLLM）在一个去噪步内并行提交多个 token，这些 token 由各自的边缘分布独立采样，彼此不可见。我们在复现 d-OPSD 的基础上，用逐步探针检验了三件事：同步提交的 token 之间是否存在冲突；d-OPSD 的 future PI 能否补偿这种冲突；冲突从何而来。结果表明：固定配额解码下同步冲突显著存在，并且是"同时决定"所特有的；future PI 能缓解约三分之一的冲突，但这种缓解几乎不针对同步兄弟，更像是补充了一般的未来上下文；PI 在冲突位置更倾向于让模型暂缓提交，说明其中含有现有 token 级蒸馏没有利用的决策信号；改用置信度阈值解码后，冲突小一个数量级。

---

## 1 研究动机

### 1.1 并行解码的分解误差

dLLM 每步揭开若干 mask 位置，记这一步提交的位置集合为 C_t。同一步的 token 是按各自的边缘分布独立采样的：

```
p(x_i, x_j | S_t)  ≈  p(x_i | S_t) · p(x_j | S_t)        i, j ∈ C_t
```

当 x_i 与 x_j 强相关时，这个近似就会出错。例如补全 "___ ___ 是美国城市"：第一位在 New / San 之间各占一半，第二位在 York / Francisco 之间各占一半。每个位置单独看都合理，独立采样却有一半概率得到 "San York"。问题不在于 Transformer 不知道两个位置相关，而在于同一次前向中两个位置都还是 [MASK]，**无法以对方的实际取值为条件**。

### 1.2 现有 d-OPSD 的监督粒度

d-OPSD 用模型自己最终生成的部分 token（self-future）作为特权信息（PI）构造 teacher，在每个去噪步上把 teacher 的分布蒸馏给 student。这种监督作用在**逐位置的分布**上；而同一步提交的多个 token 是否相容，属于**并行决策**层面的问题，不在它直接优化的范围内。

> **核心论点**：token 预测准确 ≠ 并行决策协调。

### 1.3 研究路线的收敛

| 曾考虑的方向 | 放弃原因 |
|---|---|
| **提纯 PI**：剔除 self-future 中的冗余与噪声 | 冗余不等于有害；没有证据表明"PI 越纯，推理越好"；NUS 的实验反而显示 future 给得越多越好 |
| **学习揭开时机**：判断哪些 token 可以安全并行 | 与 PUNT、SPEED、DAPD 等解码调度工作高度重叠 |
| **兄弟条件蒸馏**：teacher 看到兄弟，student 去模仿 | 推理时看不到兄弟；对兄弟的所有取值求平均后，恰好退化为原来的边缘分布 |
| **共享隐变量**：给同步 token 提供共同条件 | VADD、DiLaDiff 等已有工作 |

因此，在设计方法之前，需要先确认两件事：**这个现象是否存在**，以及**现有 PI 是否已经解决了它**。

## 2 研究假说

- **H1　同步冲突**：在固定配额解码下，同步提交的 token 之间存在显著的、提交时未被处理的相互依赖，并且这种依赖是"同时决定"所特有的。
- **H2　PI 补偿**：d-OPSD 的 future PI 能吸收这种依赖：给定 PI 后，同步 token 之间的剩余依赖减弱、趋于条件独立；并且这种吸收针对同步兄弟，而不是对任意上下文都有的一般效应。
- **H3　决策信号**：PI 除了调整 token 概率，还带有"这个位置应该暂缓提交"的决策信号。
- **H4　冲突来源**：冲突主要来自固定配额把低置信度的 token 强制一起提交。

H1 是整个方向的前提；如果 H2 完全成立，说明现有方法已经覆盖了这个问题，研究空间也就不存在了。

## 3 实验设置

### 3.1 模型与解码

- **模型与训练**：LLaDA-8B-Instruct，使用 d-OPSD 官方代码在 GSM8K 训练集上训练。
- **固定配额解码**（论文协议）：生成 256 个 token，共 128 步，block 大小 32，每步提交置信度最高的 **2** 个 token。
- **阈值解码**（对照）：每步提交所有置信度 > 0.9 的位置（至少 1 个），每步提交多少个不固定。
- **探针数据**：从 GSM8K 测试集固定抽取 300 题，温度 0.9 采样，每题一条 rollout，按最终答案分为答对组和答错组。第 4.2–4.8 节都在**未训练的 base 模型**上做；这和 d-OPSD 训练时 teacher 的设定一致，即 teacher 就是 base 模型加 PI。

### 3.2 探针设计

对每条 rollout 的每一步，固定当时的真实状态 S_t 和这一步实际提交的 token，再分别做以下几种前向：

| 视图 | 在 S_t 上额外填入 | 得到的分布 |
|---|---|---|
| 学生 | — | p_S |
| 学生 + 兄弟 | 同一步另一个提交位置的实际取值 | p_sib |
| 学生 + 对照 | 一个稍后才提交的匹配 token | p_ctrl |
| 教师 | PI | p_T |
| 教师 + 兄弟 / 对照 | PI，再加兄弟 / 对照 | p_T,sib / p_T,ctrl |

- **PI**：从下一个 block 开始，随机取 25% 的位置填入最终 rollout 的 token，与 d-OPSD 训练时的 PI 形式相同。PI 不覆盖当前 block，所以不会泄露本步的答案。
- **对照 token**：和兄弟在同一个 block，到当前位置的距离、置信度都与兄弟接近，但比兄弟晚约 1 步提交。它和兄弟一样"多提供一个已知 token"，区别只在于它决定时已经看到了当前 token。

图中的误差棒和阴影都是 95% 置信区间，按 rollout 做 bootstrap 得到。

### 3.3 评估指标

记 y_i 为位置 i 实际提交的 token。log 取自然对数（单位 nat）：差 0.1 大约对应概率变化 10%，差 −1 大约对应概率变成原来的 37%。

| 指标 | 定义 | 含义 |
|---|---|---|
| **兄弟影响 D_S** | log p_sib(y_i) − log p_S(y_i) | 即 y_i 与兄弟之间的**点互信息**，两者独立时为 0。> 0 表示兄弟支持 y_i；< 0 表示兄弟否定 y_i，即**冲突**。\|D_S\| 衡量依赖强度 |
| **分布变化 JS_sib** | JS(p_S, p_sib) | 看到兄弟后整个词表分布的变化，不只看 y_i |
| **对照影响 D_S,ctrl** | log p_ctrl(y_i) − log p_S(y_i) | 多看一个非同步 token 带来的变化，用来排除"多给任何一个 token 都会改变预测"的解释 |
| **教师侧兄弟影响 D_T** | log p_T,sib(y_i) − log p_T(y_i) | 已经有 PI 时，再看到兄弟还会变化多少。如果 PI 已经包含了兄弟的信息，应有 \|D_T\| < \|D_S\| |
| **PI 缓解量** | \|D_S\| − \|D_T\| | PI 让兄弟影响缩小了多少；对照 token 同样计算一份 |
| **兄弟特有缓解** | (\|D_S\| − \|D_T\|) − (\|D_S,ctrl\| − \|D_T,ctrl\|) | 扣掉 PI 对任意上下文都有的缓解之后，**专门针对同步兄弟**的那一部分 |
| **方向一致性** | cos(p_T − p_S, p_sib − p_S) | PI 引起的分布变化与"看到兄弟"引起的分布变化是否同向；以 cos(p_T − p_S, p_ctrl − p_S) 为对照 |
| **PI 增益 g** | log p_T(y_i) − log p_S(y_i) | PI 把 y_i 的概率拉高还是压低 |
| **PI 作用类型** | 强化：teacher 首选为 y_i 且 g > 0；暂缓：teacher 首选为 y_i 但 g ≤ 0；改向：teacher 首选不是 y_i | 把 PI 的作用分为"更确定""同向但先别急""换成别的词"三类 |
| **顺序重合度** | 学生本步提交的位置中，同时落在 teacher 置信度前 \|C_t\| 名里的比例 | 如果由 teacher 来挑本步提交哪些位置，会不会挑得一样 |
| **过早提交率** | 已提交的 token 中，teacher 置信度排在本 block 后一半的比例 | teacher 认为"提交得太早"的比例 |
| **顺序相关** | 学生与 teacher 在 block 内置信度排序的 Spearman 相关系数 | 两者对"先定谁、后定谁"的看法有多一致 |
| **成对共增益** | 同一步的 token 对中两个 token 都满足 g > 0 的比例，减去同 block、同距离但不同步的 token 对的这一比例 | PI 的作用是否按步成组出现 |

这些指标是按假说组合使用的：**D_S 对比 D_S,ctrl** 检验 H1；**PI 缓解量和兄弟特有缓解**检验 H2 是否成立、是否有针对性；**方向一致性**检验 PI 通过什么途径起作用；**作用类型和解码顺序**检验 H3；**比较两种解码方式下的 D_S** 检验 H4。

## 4 结果与分析

### 4.1 复现：准确率

| GSM8K（生成长度 256） | LLaDA-8B-Instruct | + d-OPSD | 提升 |
|---|---|---|---|
| 清华论文（全测试集） | 76.0 | 81.0 | +5.0 |
| 本文复现（300 题子集） | 78.3 | 82.7 | +4.4 |

复现结果与论文一致：最优 checkpoint 出现在第 448 步，论文报告的是第 425 步。继续训练会导致崩溃，第 1152 步准确率降到 59.3%，第 1344 步只剩 18.0%。

### 4.2 H1：同步提交的 token 之间是否冲突？

**答：是。约四分之一的 token 被同步兄弟否定；答错的 rollout 冲突更严重。**

> 【此处贴图 1】`results/pipeline_gsm_20261002/figs/fixed_base/sibling_gap.png`

**图 1**：固定配额解码下兄弟影响 D_S（左）与分布变化 JS_sib（右）的累积分布。

两张子图的纵轴都是累积 token 比例：曲线在 x 处的高度，表示指标不超过 x 的 token 占多少。蓝线是答对组（225 条），橙线是答错组（75 条），虚线是各组均值。左图横轴的 Δ_i 就是 D_S。曲线在 0 附近几乎垂直，说明多数 token 基本不受兄弟影响；**向左一直延伸到 −10 的平缓尾部，就是被兄弟强烈否定的 token**。右图中曲线越靠右，说明分布变化越大。

约 **26%** 的 token 满足 D_S < 0，少数 token 的概率甚至下降好几个数量级。D_S 的均值为 **−0.13**，也就是看到兄弟后，已提交 token 的概率平均下降约 12%。答错组更严重（均值 −0.16）：在左图的负尾部、右图的整条曲线上，橙线都落在更不利的一侧。这就是本文所说的**冲突**：两个 token 已经被一起提交，但如果当时能看到兄弟的实际取值，模型并不会选择当前这个 token。

### 4.3 H1：冲突是否为同步提交所特有？

**答：是。同样多看一个 token，看兄弟会降低 y_i 的概率，看稍后提交的 token 反而会提高它。**

> 【此处贴图 2】`results/pipeline_gsm_20261002/figs/fixed_base/C_sibling_vs_control.png`（仅保留左半部分）

**图 2**：逐 token 配对差值 D_S − D_S,ctrl。

每根柱子是同一个 token 上"看兄弟"与"看对照"两种影响之差的平均值，误差棒是 95% 置信区间。柱子低于 0，表示兄弟比对照更否定 y_i。

差值为 **−0.117**（答错组 −0.153），置信区间远离 0。分开来看，对照 token 的影响平均为 **+0.02**，兄弟的影响为 −0.13。对照 token 决定时已经看到了 y_i，所以和 y_i 相容；兄弟没有这个机会。因此冲突来自"同时决定、互不可见"，而不是"多了一个 token"本身。**H1 成立。**

### 4.4 H2：future PI 能否补偿同步冲突？

**答：部分能，但没有针对性。PI 把兄弟影响缩小了约三分之一，对普通上下文的影响也缩小了同样的幅度。**

> 【此处贴图 3】`results/pipeline_gsm_20261002/figs/fixed_base/B_coordination_gap.png`

**图 3**：学生与教师在"看兄弟"和"看对照"时，y_i 的 log 概率平均变化（左），以及 PI 带来的改变量 D_S − D_T（右）。

左图从左到右四列依次为 D_S（兄弟）、D_T（兄弟）、D_S（对照）、D_T（对照）。圆点是均值，竖线是置信区间。只统计有匹配对照的 token（约 94%），所以数值和图 1 略有差异。右图的正负号需要注意：兄弟一列为负，是因为 D_S 本身为负、PI 把它往 0 拉；对照一列为正，是因为 D_S,ctrl 本身为正、PI 同样把它往 0 拉。**两列表示的都是同一件事：PI 让额外 token 的影响变小。**

PI 把兄弟影响从 −0.098 拉到 −0.075，把对照影响从 +0.019 拉到 +0.009。按绝对值统计全部 token，兄弟影响缩小了 **32%**（|D_S| 0.211 → |D_T| 0.144），83% 的 token 满足 |D_T| < |D_S|；但对照影响也缩小了 **38%**。扣掉这部分后，兄弟特有的缓解只有 **+0.010 nat**。答对组和答错组的缓解幅度也相近，看不出"成功的 future"有什么特别作用。**H2 中"能吸收"成立，"有针对性"不成立。**

### 4.5 H2：PI 通过什么途径起作用？

**答：通过补充未来上下文，而不是提供兄弟的取值。**

> 【此处贴图 4】`results/pipeline_gsm_20261002/figs/fixed_base/pi_vs_sibling_direction.png`

**图 4**：PI 引起的分布变化与兄弟引起的分布变化之间的余弦相似度，左图为累积分布，右图为 cos > 0 的比例。

左图的黑色竖线是 0，虚线是均值；0 处那一段竖直跳变，对应两种变化里有一种几乎为零的 token。右图的虚线 0.5 是方向随机时的水平。

**67%** 的 token 上，PI 与兄弟把分布往同一方向推。单看这个数，PI 似乎带有兄弟的信息；但 PI 与对照同向的比例更高，达到 **74%**，逐 token 配对后的 cos 差为 −0.13。所以 PI 的作用更接近"让模型多知道一些未来内容"，而不是编码了同步兄弟之间的依赖。这和 4.4 的结论一致。

### 4.6 H2：PI 的作用是否具有步级结构？

**答：有，但幅度很小。**

> 【此处贴图 5】`results/pipeline_gsm_20261002/figs/fixed_base/A_cogain.png`

**图 5**：同步 token 对与距离匹配的非同步 token 对中，两个 token 都被 PI 拉高的比例。

深色柱是同一步提交的 token 对，浅色柱是同 block、同距离但不同步的 token 对，浅色柱上的误差棒是置换基线的波动范围。柱顶标注了两者的差值、95% 置信区间和置换检验的 p 值。讨论文档中原来的 CoGain 定义，在每步 token 数固定时，打乱前后的均值不会变，所以这里改成了成对比较。

同步 token 对的比例为 77.6%，比基线高 **2.9 个百分点**（答错组 +3.2），p = 0.002，这已经是 500 次置换所能得到的最小值。PI 的作用带有一点按步成组的结构，但不足以改变 4.4 的结论。

### 4.7 H3：PI 是否带有暂缓提交的信号？

**答：是。在冲突位置，teacher 更倾向于暂缓提交；师生对提交顺序的分歧也很大。**

> 【此处贴图 6】`results/pipeline_gsm_20261002/figs/fixed_base/pi_effect_types.png`
>
> 【此处贴图 7】`results/pipeline_gsm_20261002/figs/fixed_base/decoding_order.png`

**图 6**：PI 作用类型的分布（左），以及按有无冲突划分后"暂缓或改向"的比例（右）。
**图 7**：顺序重合度（左）、过早提交率（中，分为全部、冲突、非冲突三组）、block 内的顺序相关（右）。

图 6 右侧左组为 D_S < 0（冲突），右组为 D_S ≥ 0。图 7 中，顺序重合度和顺序相关越高，说明师生越一致；过早提交率越高，说明 teacher 越不认同学生当前的提交。

大多数情况下（85%），PI 只是让 y_i 更确定。但**在冲突位置，暂缓或改向的比例从 13.3% 升到 19.6%**（答错组从 16.8% 升到 24.8%）。如果由 teacher 来挑每步提交哪些位置，只有约 **54%** 和学生实际的选择一致。约 **20%** 的已提交 token 被 teacher 认为提交过早，冲突时这一比例升到 24%。block 内的排序相关只有 **0.37**。由此可见，PI 中包含"这个位置现在不该定"的判断，而 d-OPSD 的 token 级蒸馏只把它当作概率变化来学习。**H3 成立。**

### 4.8 H4：冲突是否源于固定配额？

**答：是。改用阈值解码后，冲突小一个数量级，而且不随并行度增加而变强。**

> 【此处贴图 8】`results/pipeline_gsm_20261002/figs/thr_base/sibling_gap.png`
>
> 【此处贴图 9】`results/pipeline_gsm_20261002/figs/thr_base/threshold_sibling_vs_parallel.png`

**图 8**：阈值解码下 D_S 与 JS_sib 的累积分布，画法和图 1 相同。
**图 9**：阈值解码下，D_S 与 JS_sib 随同一步提交 token 数 |C_t| 的变化。

比较图 8 和图 1 时要注意横轴范围：图 1 为 −10 到 1，图 8 只有 −0.06 到 0.1。图 9 的横轴是同一步提交的 token 数，圆点是均值，竖线是置信区间。

在阈值解码下，|D_S| 从 0.211 降到 **0.021**，平均 D_S 变成 **+0.017**，即兄弟以支持为主，冲突 token 只占约 7%。即使一步提交 9 个以上 token，D_S 仍然为正，JS 也低于 0.008。阈值解码只把模型已经有把握的 token 放在一起提交，而这些 token 本来就相容；固定配额则会把还没有把握的 token 也凑进来。准确率的结果与此一致：同为 base 模型、温度 0.9，阈值解码为 79.3%，固定配额为 75.0%。**H4 成立。**

### 4.9 补充：训练后的学生是否更协调？

在第 448 步，学生自身的 |D_S| 从 0.211 降到 0.140（−34%），但它对对照 token 的敏感度也下降了 42%（0.118 → 0.069）。这说明训练让模型整体更自信、对一切额外信息都更不敏感，而**不是专门学会了同步协调**。在阈值解码下，训练几乎没有带来准确率提升（79.3% → 79.7%）。

## 5 结论

| 假说 | 结论 | 关键证据 |
|---|---|---|
| H1 同步冲突 | **成立** | 26% 的 token 被兄弟否定；兄弟与对照的影响差为 −0.117 |
| H2 PI 补偿 | **部分成立**：能缓解，但没有针对性 | 兄弟影响缩小 32%，对照影响缩小 38%，兄弟特有部分仅 +0.010 |
| H3 决策信号 | **成立** | 冲突位置的暂缓 / 改向比例为 19.6%，非冲突位置为 13.3%；师生顺序重合度仅 54% |
| H4 冲突来源 | **成立** | 阈值解码下 \|D_S\| 小一个数量级，且不随并行度增加 |

**对研究方向的启示：**

1. **问题真实存在。** "token 预测准确 ≠ 并行决策协调"在固定配额解码下得到了实证支持。
2. **研究空间尚未被占据。** d-OPSD 的 future PI 只是顺带缓解了冲突，"针对并行决策的监督"仍然有待设计。
3. **切入点。** PI 中"暂缓提交"的决策信号没有被 token 级蒸馏利用。
4. **实验设置。** 后续应采用更高的并行度（例如 256 个 token 用 64 步，每步提交 4 个），这时问题更突出，也更接近 dLLM 追求加速时的实际场景。（待验证）

**局限**：只用了单个随机种子、300 道 GSM8K 题、温度 0.9；对照 token 是稍后提交的，所以 4.3 节严格来说比较的是"同时决定"与"先后决定"。
